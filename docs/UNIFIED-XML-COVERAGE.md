# Unified XML implementation coverage

The default writer uses the single shared format definition in both C# and TypeScript. Explicit schema XML can also be passed to `HmiScreenToUnifiedXmlConverter`. That writer discovers control contracts by semantic type, writes editable scalar fields and owned parts, and supports IO fields, symbolic IO fields, rectangles, faceplates and screen windows when the selected catalog declares them. It preserves JavaScript events, globals, async settings, triggers, tag dynamizations and resource-list dynamizations. The writer reports missing mappings and marks export incomplete; selecting a catalog does not establish coverage of every SDK type.

Engineering tag settings live in `HmiDynamicProperty.UnifiedTagDynamization` / `unifiedTagDynamization`. They include qualified tag/resource names, address, datatype, PLC tag, read-only/indirect flags and an editable value-converter mapping table. Ordered entries retain ranges, exact 64-bit masks, typed values/alternate values and flashing settings. IO process values, IO mode and owned input behavior are first-class properties. Neither writer reads `SourceData` or `SourceProperties` to recreate exported content.

The initial add-in comparison used `501 StartScreen` and `502 Functions`. Their controls were all recognized (graphic view, buttons and static text). The XML reader now models background patterns and alternate colors, button content settings, graphic references, wrapping/trimming, security/quality/style settings and content spacing/split/text-position. Localized screen display names and all exposed font names/weights are editable model values. One shared catalog is used by both default writers and readers; older exported-file catalogs are not supported.

Native readers now separate event and property-script bodies from their function signatures, definition areas and async settings. The runtime assembles executable code from these fields. Native image references retain names and IDs even when their bytes are unavailable. Images and tag/text-list resources still require the owning project.

The C# and TypeScript XML-model paths reproduce the full canonical object graphs of the two comparison exports, including values, ownership, creation recipes and references. This establishes those XML-model round trips; by itself it does not establish native-project reader equivalence or a successful subsequent TIA import. Native fill patterns now map from their packed backend values into the shared semantic enum, and explicit screen appearance/focus settings are read independently from preview defaults.

Native readers map the persisted property keys using the SDK base-127 identifiers and verified hexadecimal Unicode encoding. The paired tables include the positive V21 SDK property identifiers. Selected style values include content, padding, style classes, wrapping/trimming and read-only settings; native getter defaults are applied after palette inheritance. Geometry, opacity, rotation, focus and alternate-color dynamics remain editable. Automatic tags, explicit tags, fixed cycles and named custom cycles retain their distinct engineering trigger settings.

Native formatted captions now wrap plain text in the engineering body/paragraph markup and expand missing default translations only to the project's `CoreDataContainer.UsedCultures`. Explicit empty translations remain empty and invariant category identifiers are excluded. Resource names in scripts and resource-list bindings use the project-qualified reference mapper. Custom authorization names come from the right's Name; the no-right display label follows the host UI culture (verified German/English). The two saved comparison screens now reproduce the add-in's full canonical graphs from the native TypeScript reader as well as from XML models. This is evidence for those screens, not all control families.

Scoped external PLC-tag paths and property-event handlers are now modeled in both languages. Native extraction checks the soft-link consumer and preserves saved paths for disconnected links, arrays and inherited members. Change/quality-code handler scripts retain their independent property names, globals and async settings. The V21 property-event extension is an additional immutable profile; old profile files remain unchanged.

Additional exact typed scalar mappings cover clock visibility, web/media URLs and autoplay, bar origin values and shared grid/filter/appearance settings where the selected contract declares them. Media Url maps to the existing model Source property in static values, scripts and tag dynamics. Container ownership is retained recursively when a contract declares owned ScreenItems; this is separate from external faceplate definitions.

Remaining work includes complete engineering serialization of alarm views/columns and their header/content parts; trend-area, axis and pen ownership/references; parameter-control columns and toolbar/status structures; and unverified rich-text/default combinations. Existing native preview models for these controls do not establish full XML export coverage. Public API inventory entries alone are not encoding contracts. The authorization no-right label needs validation for other TIA UI languages and when host/TIA cultures differ. Native getter defaults must be established from the corresponding TIA implementation/profile, rather than copied from a sample screen. The public API inventory is broader than the released encoding contracts; listing a type in the inventory does not make it exportable.

The Siemens V21 Openness implementation also limits what its graph can represent. `HmiOpennessFont.GetFontNameEnum` maps native font families outside Arial, Times New Roman, SimSun and Siemens Sans to Arial. Its weight setter rejects changing to Light or SemiBold. A matching add-in graph consequently cannot certify preservation of every native font setting. Full native font fidelity needs a versioned format extension and a capable TIA adapter; the model must retain the actual values. The writer emits the SDK font aliases and maps other native families to Arial with a diagnostic, retaining the actual native family in the model. This matches the public font projection, without establishing full native-font preservation.

Runtime preview handles disabled, explicit-tag, automatically discovered static-tag and fixed-cycle script scheduling. CustomCycle resolves the named project cycle. Computed automatic tag-subscription discovery remains a runtime gap; their engineering values are retained independently by the XML model.


## TypeScript platform adaptation

The XML reader's C# control factory discovers public concrete `HmiScreenItemBase` types through assembly reflection. TypeScript has no assembly/type reflection, so `HmiUnifiedControlConstructors.ts` explicitly imports the matching model constructors; catalog type identities select from that registry. Both factories use the same SDK aliases. Regression checks cover IO controls and authoring faceplate/window/shape contracts. Keep the registry aligned when adding model control classes; replace it only if the package gains a shared generated constructor registry. This is constructor discovery only, not a separate TypeScript wire contract.

## Runtime versus engineering data

The runtime evaluates preserved range/bitmask mappings and text/graphic resources directly from the engineering binding settings, including indirect tag names. Flashing settings are retained for engineering export; this change does not add flashing scheduling to preview. Project dependencies remain external. Successful offline graph comparison is separate from a verified import into TIA; no live import is certified by these checks.


The XML grammar/model are shared across producer API versions. Parsing a known contract under another well-formed API-version label does not establish a native adapter for that release. The single shared catalog declares stable format defaults; native adapter capability/version handling remains separate.

Multilingual XML stores direct formatting content without body or redundant unstyled paragraph wrappers. Empty formatted entries preserve their language; plain empty values remain explicit. The C#/TypeScript and transfer codecs preserve styled/multiple paragraphs, body attributes, mixed content and whitespace. Readable script bodies/global definitions use xml:space="preserve", LF in XML and CRLF in engineering strings; encoded code-unit payloads remain explicit.
