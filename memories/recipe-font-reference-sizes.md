# Recipe control raw font sizes

HmiRecipeControl exposes four optional HmiProperty<double>/HmiProperty<number> reference-device sizes: header, content, status bar and combo box. Recipe HTML writes distinct data attributes and does not turn them into fonts or CSS scaling values. Advanced conversion uses persisted role-specific keys and the existing finite numeric/style precedence behavior. Shared fields do not prove Professional or Unified native mappings.

Advanced recipe raw-font increment: the generic V19/V20 RecipeView styles contain HeaderFont_ReferenceDeviceSize, Font_ReferenceDeviceSize, StatuslineFont_ReferenceDeviceSize and ComboboxFont_ReferenceDeviceSize. Both converters map these through the existing finite numeric helper to independent recipe-control header/content/status-bar/combo-box FontReferenceDeviceSize properties. Shared HTML exposes separate raw metadata attributes, without creating fonts or interpreting these values as CSS pixel sizes. Item overrides follow styles; invalid values retain inherited settings and absent fields stay absent.

Validation: four main Advanced recipe checks per language passed without skips, extending generic native style checks with finite/invalid overrides, distinct role values, missing fields and HTML. Shared recipe selections passed 58 C# and 57 TS checks, including 13 new metadata cases each. Both TS builds and all three shared C# targets passed. Native instance/export/visual comparisons, font scaling and the full control/property/recipe goal remain open; native style evidence is not complete instance coverage.
